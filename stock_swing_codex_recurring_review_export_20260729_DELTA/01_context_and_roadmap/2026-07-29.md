## 概要

昨日（07-28）の ADBE 売買について「買ってすぐ売って赤字」という報告を受け調査。
実際には **ADBE は売られておらず**、reconciler のバグによる phantom close（幽霊クローズ）であることを特定・修正した。

## 問題の詳細

### 現象
- 07-28 13:35 UTC: ADBE 新規買い 160株 @ $245.53
- 07-28 13:45 UTC: ADBE が $218.40 でクローズされた記録 → 損失 -$4,340.80

### 根本原因: reconciler の stale fill replay バグ

```
07-23: 旧 ADBE ポジション (broker_open_0257_ADBE) 売り
       exit_broker_order_id: 5874c9bf @ $218.40 (trailing_stop)
       ↓
07-25: rebuild 実行 → broker_open_0257_ADBE が state.trades から消滅
       しかし trade_events.jsonl の trade_closed イベントは残存
       ↓
07-28: 新規 ADBE 160株 買い
07-28: reconcile 実行
       → processed_sell_order_ids を state.trades のみから構築
       → 5874c9bf が「使用済み」リストにない
       → 07-23 の古い sell fill を新規ポジションに再適用
       → phantom close at $218.40 (損失 -$4,340.80)
```

### ブローカー確認
- **ADBE: 160株 open @ $246.74 avg、現在 $248.28（+$245.80 含み益）**
- 実際の売り取引は一切存在しない

## 修正内容（commit 36d6af3）

### Fix 1: reconcile_orders.py — processed_sell_order_ids の構築を強化

**Before**: `state.trades` の closed エントリのみから構築
```python
processed_sell_order_ids: set[str] = set()
for trade in tracker.state.trades:
    if trade.get("status") == "closed":
        ...
```

**After**: `quarantined_trades` + `trade_events.jsonl` の全 `trade_closed` イベントも追加
```python
# state.trades からの構築（従来）
...
# quarantined_trades からも追加
for trade in tracker.state.quarantined_trades:
    ...
# trade_events.jsonl の全 trade_closed イベントからも追加（最終防衛線）
if _te_path.exists():
    for _ev in _te_path:
        if _ev.event_type == "trade_closed":
            processed_sell_order_ids.add(_ev.broker_order_id)
```

## 学んだこと

**rebuild は state.trades の closed エントリを再構築するが、完全でない場合がある。**  
exit_broker_order_id の「使用済み」判定は `trade_events.jsonl` を正規のソースとして使うべき。  
`trade_events.jsonl` は append-only の event log であり、rebuild に影響されない最も信頼できるソース。
