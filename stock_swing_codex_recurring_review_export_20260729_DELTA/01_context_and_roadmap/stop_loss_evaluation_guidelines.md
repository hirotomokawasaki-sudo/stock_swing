# Stop Loss 評価指針（2026-07-27 策定）

## 1. Stop Loss の本質的役割

Stop loss の目的は「利益を生むこと」ではなく、「負けトレードを早期に終わらせること」である。

> **WR（勝率）や PF（利益係数）での評価は目的と評価軸の不一致であり、誤った判断を招く。**

| 指標 | trailing_stop での意味 | stop_loss での意味 |
|------|----------------------|------------------|
| WR | 利益で終わった割合 | **誤発動（早期売りすぎ）の割合** |
| PF | 利益効率 | **評価対象が違う** |
| net PnL | 収益 | 「止損がなければ追加でいくら失ったか」は測れない |

---

## 2. 正しい評価指標

### 2-1. 正しい止損率（Primary Metric）

```
正しい止損率 = exit後にさらに価格が下落したトレードの割合
```

- **目標値: ≥ 70%**
- 実測値（2026-07-27 分析、48件）: **89.6%**（全期間）/ **100%**（07-10〜）

解釈:
- 正しい止損率が高い = stop_loss はその後の損失を正しく防いでいる
- 正しい止損率が低い = stop の閾値・タイミングが早すぎる（誤発動が多い）

### 2-2. 誤発動率（Secondary Metric）

```
誤発動率 = 止損後に entry_price まで回復したトレードの割合
```

- 目標値: ≤ 30%
- 実測値: 31.2%（全期間）/ 0%（07-10〜）

注意: 誤発動率が高い = 保有していれば損失がなかった案件が多い

### 2-3. 損失限定効果（Counterfactual Savings）

```
損失限定効果 = 止損がなければ追加で失った推定金額
```

- 実測値（07-10〜、11件）: **-$12,892**（止損による損失回避額）
- 実際の止損損失: -$21,180 → 止損がなければ合計 -$34,072（**38%の損失軽減**）

## 3. 回復期間別の分類（post-exit drift 分析）

48件の true stop_loss（PnL < 0）を 60日追跡した結果：

| 分類 | 件数（判断確定） | avg_ret | 意味 |
|------|--------------|---------|------|
| 15日以内に entry_price まで回復 | 10/21件 | **-2.9%** | 早期売りすぎ（誤発動） |
| 16-30日で回復 | 1/21件 | -7.0% | 長期保有で回避可能だった |
| **30日超も未回復（真の止損）** | 10/21件 | **-8.2%** | 正しい止損対象 |

**境界線: -5〜-6% あたりで性質が大きく変わる。**

## 4. 止損幅別の特性

| 止損幅 | T+5日 exit_price 超え率 | T+10日 exit_price 超え率 | 評価 |
|--------|----------------------|----------------------|------|
| **小 (< -5%)** | 78% | **89%** | ⚠️ 誤発動が多い |
| 中 (-5〜-8%) | 45% | 17% | ✅ 止損が正しく機能 |
| 大 (> -8%) | 82%（一時的 bounce） | 30% | ✅ 即時 exit が正解 |

**小さな止損（< -5%）は1週間でほぼ回復する。ノイズ起因の誤発動が主体。**

## 5. 改善済みロジック（Plan A: Tiered min_hold）

**commit: 52736ca（2026-07-27）**

止損幅に応じて min_hold（最低保有日数）を段階化した：

| 現在の下落率 | min_hold | ゾーン | 根拠 |
|------------|----------|--------|------|
| > -5% | **7日** | ノイズ域 | 78%が7日以内に回復 |
| > -8% | **3日** | 中間域 | 45%がT+5回復、3日様子見 |
| ≤ -8% | **1日** | 真の止損域 | 即時 exit が損失最小化 |
| ≤ -12% | **即時** | emergency bypass | どの tier も無視して即 exit |

シミュレーション結果（48件）: stop_loss 損失 **-$167K → -$126K（+$41K 改善）**

設定ファイル: `config/strategy/simple_exit_v2.yaml`
```yaml
tiered_min_hold_enabled: true
tiered_min_hold_levels:
  - threshold_pct: -5.0
    min_hold_days: 7
  - threshold_pct: -8.0
    min_hold_days: 3
```
ロールバック: `tiered_min_hold_enabled: false` に変更するだけ。

## 6. 誤りやすい評価パターン（Anti-patterns）

### ❌ WR 30% を目標値にする
- stop_loss WR = 18.6% は「機能不全」ではなく「ほぼ全件が正しい止損だった」を示す可能性がある
- 後続の価格追跡なしに WR で判断してはいけない

### ❌ 直近期間の WR=0% を panic する
- 07-10〜07-27 の stop_loss WR = 0%（11件全て負け）
- post-exit 分析では 11件全てでさらに株価が下落 → **止損が全て正解だった**

### ❌ 止損回数が多い = 設定が悪い と判断する
- sector shock 等の外部要因でクラスタリングすることがある
- 07-16（SMH -3.7%）などセクターショック日の集中発生は構造的なもの

### ❌ 保有継続の方が必ず良いと仮定する
- T+5（5日後）は62%のケースで保有の方が良かったが、T+10では38%に逆転
- 「もう少し保有すればよかった」は結果論であり、事前には判断できない
