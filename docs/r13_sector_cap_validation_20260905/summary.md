# セクター集中上限 反実仮想検証 — サマリー（2026-09-05）

## 検証対象ルール（反実仮想）

> エントリー実行後の「同一セクター保有notional / equity」が cap を超えるなら、
> そのエントリー自体をブロックしていたら実績はどう変わったか。
> cap ∈ {30%, 40%, 50%}（equity比）。

- スクリプト: `scripts/analyze_sector_cap_counterfactual.py`（読み取り専用）
- 対象: `data/tracking/pnl_state.json` の closed 357件 + open 5件
  （openは露出計算にのみ使用、PnL差分からは除外）
- ポートフォリオ再構成: notional = qty×entry_price、entry_time〜exit_time保有。
  equity = baseline $1M（2026-05-12起点）+ 実現PnL累積（動的）
- **逐次シミュレーション**: エントリーを時系列順に処理し、ブロックされた
  ポジションは以後の露出計算から除外（cap間で結果が非単調になり得る、後述）
- 現行本番との対応: `PositionSizingPolicy` の `max_sector_exposure_pct=0.55`
  （equity比55%、サイズ縮小）に対し、本検証は「より低い cap での全量ブロック」

## セクター分類

1. **優先**: `config/reference/symbol_registry.yaml` の `sector` フィールド
   （G6 canonical registry、R13-D `SectorMomentumFeature` と同一ソース）。
   registry 内の `semis` キーは `semiconductor` に正規化
   （`position_sizing.py` の `SYMBOL_SECTORS` が同概念を `semis` キーで保持する
   表記揺れを吸収）。**取引58銘柄すべて registry でカバー**（fallback 未使用。
   スクリプト内に semiconductor/other_tech/etf/other の簡易静的 fallback マップを
   fail-safe として保持、根拠コメント付き）。
2. **補助グルーピング**: registry の `is_semiconductor_related` フラグ（33銘柄、
   ETF・個別株・JP銘柄を跨ぐ）を1グループとして同じ cap を適用した
   「半導体関連連結」ビュー。半導体ETF（SOXX/SMH/FTXL/CHPX等）と個別半導体株が
   registry sector 上は同じ `semiconductor` だが、クラスタとしての連結露出を
   直接測る意図（R5-v2 correlated cluster cap と同じ発想）。

## キーファインディング

1. **cap 30% は両グルーピング・両コホートで改善**。特に直近コホート
   （exit>=07-16、baseline PF 0.634）でブロックされるのは
   **FTXL（08-17エントリー→08-24セルオフ stop_loss -$6,706）と
   CHPX（同 -$6,103）**（+registry版はORCL +$118）で、
   「8/14以降の新規半導体エントリーが出血源」という既知の診断と正確に一致。
   PF 0.634→0.733/0.735。
2. **cap は Net PnL に対して非単調**（30% +$31.5k / 40% -$4.6k / 50% +$11.2k）。
   逐次シミュレーションのため cap を緩めるとブロック対象の顔ぶれ自体が変わり、
   40% では勝ち（MU +$4,519、AMAT +$6,042、SMHX +$3.5k×2等）を負けより多く
   消してしまう。**「セクター上限＝常に改善」ではなく、閾値依存で機会損失が
   回避損失を上回り得る**ことの直接的な証拠。
3. **機会損失は大きい**: cap 30%全期間でも勝ち30件 +$39,332 を同時に消しており、
   純改善 +$31.5k は「回避 $70.6k − 機会損失 $39.3k」の差分にすぎない。
4. 半導体関連連結ビュー（ETF+個別株を跨ぐ）でも方向は同じ。半導体集中の実測
   ピークは equity比 **78.2%**（2026-06-04、TSMエントリー後）で、現行の
   sizing 側 cap 55% を大きく超えた歴史がある（sizing capはブロックではなく
   縮小のため、複数銘柄の積み上げで超過し得る）。
5. **現在のオープンポジション**（2026-09-05）: open notional $151.7k
   （equity比 15.8%）。software 41.2% / cloud_software 35.1% /
   semiconductor 23.7%（MUのみ、equity比 3.7%）。**現時点の半導体関連露出は
   equity比 3.7% と低く、どの cap にも抵触しない。**

## 一次近似の限界（明示）

- ブロックで浮いた資金の再配分（他銘柄への振替・他エントリーのサイズ増）と
  複利効果は無視。実運用ならブロック分の資金が別トレードに向かい結果は変わる。
- 全量ブロックのみ検証（実運用の sizing cap は部分縮小も可能）。
- notional は entry価格固定の名目値（時価変動・含み損益は露出に未反映）。
- 直近コホートで意味のあるブロックは cap 30% の2〜3件のみで、**少数トレード
  依存**（改善の実体は FTXL/CHPX の2件 -$12.8k）。

## R5-v2 cluster cap との接続

paper_demo の `_filter_buys_by_cluster_cap()`（semis/cloud_software 等6クラスタの
BUY自動ブロック、top5_concentration 閾値40%）が既に本番実装済みであり、本検証の
「半導体関連連結 cap」はその閾値妥当性検証（R5-v2 残項目）に直接使える。
09-08 の R13-D ETFセクターローテ配線判断では、本結果（特に cap 30% が直近の
半導体出血を正確にブロックした事実と、40% の逆転＝閾値感度の高さ）を判断材料に
含めること。
