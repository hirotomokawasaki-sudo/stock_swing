## 2. 全段階の原則

1. **記述・推論・意思決定を分離する。** PFは記述値、研究打切りは資源配分、安全停止はリスク制御、優位性確認は推論、実弾は資本投入判断。
2. **入力と定義を版管理する。** `cohort_id / cutoff / input_hash / code・config・universe版 / cost_model / environment_id`を全結果に付す。
3. **未説明差を消さない。** 欠測・未対応・価格補正・除外を一覧化し、都合のよい部分だけで合格にしない。確認できないものは未検証とする。
4. **主比較は1つに固定する。** 診断用の枝を増やしても、最良の枝へ事後的に主候補を差し替えない。
5. **前向き期間は準備完了後に始める。** カレンダー日を先に固定して後付け事前登録しない。過去データの再適用は探索。
6. **リスク制御に必ず利益増を要求しない。** 許容収益低下・必要な損失抑制・単純縮小対照を事前に定義する。
7. **既存基盤を活用する。** `r11_backtest_engine_v4.py`、`rolling_walk_forward.py`、`trial_registry.py`と既存ログを優先。新しい取引プラットフォームや有料データ契約は本計画に含めない。

### 5.2 主比較と判断の意味

| 評価対象 | 必要な確認 |
|---|---|
| リスク制御の動作 | 発注前予算と集中上限の不変条件、違反/欠損時の停止、ストレスケースでの動作。相場変動による事後超過は別分類 |

| 経済性 | 費用控除後の絶対成績と低コスト・同リスクの代替運用に対する成績。リスク低減だけで黒字とはしない |

**判定値を確定する作業（F1開始の必須成果物）**:

- 許容収益減 `epsilon`、最低限必要なリスク低減、実務上意味のある主効果量 `delta`、口座/銘柄/相関グループの損失予算を先に明文化する。許容損失はユーザーの資本制約と既存ルールに整合させる。

- 主効果量・非劣性許容幅などが未確定のまま確証期間を開始しない。決められない場合は、期間を明示した計測パイロットまでとし、結果を確証に転用しない。

- 結果は `supported / not_supported / inconclusive / invalid_data` に分ける。inconclusiveを不合格や成功へ自動変換しない。リスクのみ有用・収益優位性未確認という結論を許す。

ここで定める数値は**計画の欠落を結果を見て埋めるものではなく、Phase 1/2と較正区間に基づく開始前の仕様確定タスク**。
