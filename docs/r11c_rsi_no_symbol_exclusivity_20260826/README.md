# R11-C RSI逆張り候補: 「1銘柄1ポジション」排他制御を外した本番相当検証（2026-08-26）

**背景**: `r11c_rsi_threshold_grid_rolling_wf.py`での閾値グリッドサーチ中に、
RSI逆張りフィルタの改善効果の大半が「v4エンジンの1銘柄1ポジション排他制御による
エントリータイミングシフト」に由来し、これは**本番の意思決定パス
（`RiskValidator.validate()`/`BreakoutMomentumStrategy.generate()`/
`EntryFilterEngine.filter()`/`paper_demo.py`の金額上限チェック）のどこにも
存在しないルール**であることをコード確認で突き止めた。本番は既存保有銘柄への
追加buyを金額上限までは許可する（実際`pnl_state.json`でLRCX/IBM等が複数lot
保有していることを確認済み）。

本スクリプトは、この排他制御を完全に取り除いた（同一銘柄に複数ポジション同時
保有を許可、cap機構も無効化）バックテストエンジンで、RSI逆張りフィルタの
「純粋な直接効果」のみを測定した。

## 結果

| | baseline（フィルタなし） | RSI逆張り（threshold=75.0） |
|---|---|---|
| n | 2,348 | 1,868 |
| win_rate | 73.13% | 73.23% |
| **profit_factor** | **2.1246** | **2.1370** |
| net_pnl | $457,198.42 | $358,289.44 |
| avg_return_pct | 0.0195 | 0.0192 |

## 結論: 仮説が確定的に裏付けられた

**排他制御を外すと、RSI逆張りフィルタの効果はほぼ消滅する**:
- Profit Factorの差はわずか+0.58%（2.1246→2.1370、ほぼ誤差範囲）
- net_pnlはむしろ**23.6%減少**（$457,198→$358,289）——取引数が2,348→1,868に
  減った分の機会損失が、フィルタによるPF改善分を上回っている
- win_rateもほぼ横ばい（73.13%→73.23%）

これは`r11c_v2_rigorous_rerun.py`（PF+16%改善）および
`r11c_rsi_threshold_grid_rolling_wf.py`（全閾値でsupported）で確認された
「改善効果」が、**v4エンジン固有の1銘柄1ポジション制約というバックテスト実装の
副産物であり、RSI逆張りという戦略アイデア自体の真の優位性ではなかった**ことを
確定的に示している。

## R11-C全体の結論への影響（重要な訂正）

- `docs/r11c_v2_rigorous_rerun_20260826/README.md`および
  `docs/r11c_rsi_threshold_grid_rolling_wf_20260826/README.md`で報告した
  「RSI逆張りフィルタが旧結論（見送り）を覆した」という結論は、**本番相当の
  条件下では成立しない**
- 2026-08-15の旧結論（「RSI逆張りはbaselineと実質差なし、見送り」）が、
  本番動作に近い条件下では**結果的に正しかった**ことが再確認された
- この一連の検証（v4厳密化→グリッドサーチ→排他制御除去）は、当初の
  「旧手法は不十分だったので厳密化すべき」という監査指摘は正しかったが、
  「厳密化した結果」自体にも別の実装アーティファクトが紛れ込んでいたことを
  示す教訓的な事例となった

## 教訓

1. **バックテストエンジンの実装詳細（この場合は同時保有ポジション数の制限）が、
   戦略アイデア自体の効果と見分けがつかない形で結果に混入しうる**——
   evidence-based-system-auditのアンチパターンチェックリストに新規追加すべき
   項目候補（「エンジン固有の制約が戦略効果と誤認されていないか」）
2. 「厳密な手法で再検証したら結論が変わった」こと自体を鵜呑みにせず、**その
   厳密な手法の内部で何が起きているか（個別トレードレベルでの因果関係）まで
   遡って確認する**ことの重要性が、今回2段階（cap誤仮説→タイミングシフト発見→
   本番相当検証）で実証された
3. 最終的にR11-Cの「RSI逆張り含む4候補全て見送り」という2026-08-15の判定は、
   より慎重な検証を経てもなお支持される結果となった

## 残る限界（正直な開示）

本スクリプトも完全な本番再現ではない。本番の実際の金額上限ゲート
（`position_limit_pct`、equityベースの動的計算）はモデル化しておらず、
「排他制御なし・cap制約なし」という単純化版での検証に留まる。より精密な
検証には、本番の`position_limit_pct`ロジックを固定ノーショナルではなく
ライブエクイティカーブ上で再現する追加実装が必要（今回は実施せず）。
