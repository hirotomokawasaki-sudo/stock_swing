# 購入停止銘柄の前向き観測 v1 (2026-10-28)

## 権限と目的

購入停止を維持し、再検証の優先順位を付けるための**観測・通知のみ**。
解除、PF除外リスト編集、注文、取引台帳更新、HALT解除を行う機能は持たない。
明示的な購入禁止（compliance/insider）は復帰検討の対象外。
既存のPFゲートは従来どおり再計算される。本機能は新しい永久停止ラッチではない。

## 事前固定する観測方法

- 実際のentry filter到達時にPF理由で除外されたBUYだけを、run/decision/strategy/
  strategy version/config hash/UTC日時/理由とともに新規記録する。過去の候補を遡及投入しない。
- 当該ゲートより後段の制約を通過するとは限らない。約定や「本来得られた利益」とは扱わない。
- 同一銘柄は同時に1観測。複数strategyや1日複数runを独立サンプルに数えない。
- 観測日の**翌ET取引日open → 5取引日目close**の固定期間価格診断。
  現行Exit戦略やポートフォリオを再現した仮想売買ではない。
- 既存取得済み日足のみ利用し、追加価格API・新規依存ライブラリ・DBを導入しない。
  既存post_signal_outcomesは事後取得・履歴再計算用であり、そのまま流用しない。
  Backtesting.pyも検討したが常時観測への統合に別の実行基盤が必要なため採用しない。
- ET休日・週末を除く5日すべてのOHLCVが必要。16:05 ET以降に完了日足とみなす
  （短縮日は保守的に通常時刻まで待つ）。欠損・矛盾・未来/naive日時・不正価格・品質フラグは保留。
- 元の日足ID/source/取得日時/価格/ハッシュを結果に保存し、完成済み結果は再計算しない。
- round-tripコスト控除は基準20bps、ストレス30bps。固定仮定であり、実測コストではない。

## 再検証候補の事前固定基準（経済的有効性・解除条件ではない）

同一symbol/strategy/version/config cohortで、以下をすべて満たした場合のみ
`review_candidate`（**再検証・手動承認が必要**）とする。

1. 重複しない完成観測30件以上。足りなければcollecting。
2. ストレスコスト控除後平均リターン > 0、PF ≥ 1.20。
3. 前半・後半の両方でストレス控除後平均 > 0。
4. 全観測の期間内安値ベースの最悪リターン（ストレス控除後）が -7% 以上。
5. 現在も実際のPF停止一覧に存在し、最新完了取引日の日足が有効。
   期日到来の未完成観測や、現在の設定とcohort不一致がない。

30件/PF1.20/-7%は**保守的な調査着手の目安**であり統計的有意性や将来収益を保証しない。
entry設定・実効シグナル設定の違いはcohortを分離し、現在の設定と一致しないcohortの候補通知は保留する。
通常ジョブにもopenとcloseでstock-reduced設定の差があるため、設定差でstore全体を停止させない。
評価仕様・関連sourceが変われば既存storeを混ぜず保留し、明示的新versionが必要。
日数経過、値上がり、負け取引の期間落ち、サンプル数引下げでは候補化しない。

## 通知・運用

- 現在のconsole summaryに観測数・状態を追加。候補があれば既存の`--telegram`
  定期サマリーの冒頭に表示（追加送信・別スケジュールは作らない）。送信失敗時に通知済みを偽装しない。
- 本番保存先は `data/analysis/entry_restriction_review_v1.json`。売買台帳とは分離。
  排他ロック、checksum、atomic replaceで保存。破損や書込失敗はerrorとして可視化、候補は出さない。
- dry-run/無効時は観測storeを書かない。障害は売買判断・SELL処理を変えない。
  `ENTRY_RESTRICTION_REVIEW_ENABLED=false`は観測のみ停止する。
- 候補化後も `eligible_to_trade=false`。解除には本来のExit/費用/損失制御での別検証と
  ユーザーの明示承認が必要。承認後の限定Paper再開・再停止は別変更とする。

## 検証境界

単体で正常/不足/欠損/破損/異常日足/重複/日米日時/設定変更/逆方向遷移を検証。
実CLIを隔離したrootと外部I/O fixtureで有効/無効比較し、HTTP・発注・既存制限が不変であることを検証。
初回定期実行前はimplemented/enabledであり、forward evidence-readyとは報告しない。
