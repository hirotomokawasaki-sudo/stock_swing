### 3. 根本原因調査

**Partial Fill + used_sell_order_ids バグ**

タイムライン（米東部時間 6/24）:
1. **16:00:20 ET**: paper_demo が sell 254 CRDO を送信
2. **16:00:21 ET**: ブローカーが 51株を即時部分約定
   → paper_demo インライン reconciler が 51株クローズを記録
   → `exit_broker_order_id = c0c0df3d` を保存
3. **その後**: ブローカーが残り 203株を同一注文で約定
4. **cron reconciler 実行時**:
   - `used_sell_order_ids` に `c0c0df3d` が存在 → **スキップ**
   - 203株が永久に記録されない
5. **19:55 ET**: 新規 buy 85 CRDO
   → tracker open = 35+84+84+85 = **288株**（実態 85株）

**コードの構造的欠陥**:
```
used_sell_order_ids にブローカー注文IDを追加
  ↓
同一注文の部分約定→完全約定でも「既処理」とブロック
  ↓
残りの株数クローズが永久に記録されない
```

### 4. 恒久修正実装（commit: b1c1726）

**`src/stock_swing/cli/reconcile_orders.py`**:

- `used_sell_order_ids` チェック時に partial fill completion ロジックを追加
- `recorded_qty_by_order_id` map（注文ID → 記録済み株数）を事前構築
- 注文IDが `used_sell_order_ids` に存在する場合:
  - `broker_filled_total - already_recorded = remaining` を計算
  - remaining > 0 なら **スキップせず残りを処理**
  - remaining ≤ 0 なら真の重複 → スキップ
- `effective_fill_qty` (remaining or full qty) を `record_exit` に渡す
- 記録後に `recorded_qty_by_order_id` を更新（同一ランン内の重複防止）

**テスト追加**:
