## 根本原因

**G1 race condition の再発** — 3秒 wait では不十分なケース。

| フェーズ | 詳細 |
|----------|------|
| cron | `stock_swing_paper_demo_market_open`（09:35 ET / 1-5） |
| 実行時刻 | 2026-07-21 13:35:03 UTC（= 07-20 22:35 JST） |
| 注文 | BUY 32 META, BUY 866 HPQ（broker 約定確認 OK） |
| wait | 3秒後に broker positions 再取得 |
| 問題 | **寄り付き混雑で Alpaca API 反映ラグが 3秒超** |
| 結果 | tracker に META/HPQ 記録済み ⟶ broker positions に未反映 → mismatch=2 |

**問題**: post-run guardrail が新規送信 symbol の broker API lag を本物の mismatch と誤判定していた。

**修正**:
```python

_new_buy_symbols  = {s.symbol for s in _new_submissions if s.side == "buy"}
_new_sell_symbols = {s.symbol for s in _new_submissions if s.side == "sell"}
_lag_excused = (
    (set(_bt_diff_postrun["tracker_only"]) & _new_buy_symbols)
    | (set(_bt_diff_postrun["broker_only"]) & _new_sell_symbols)

_adjusted_mismatch = _bt_diff_postrun["mismatch_count"] - len(_lag_excused)
# _adjusted_mismatch を guardrail に渡す（raw ではなく）
```
