# 2026-06-22

## Console analytics / chart data freshness recovery

### 1. Root cause confirmed
- Investigated why console analytics and charts appeared stuck after `2026-06-12`.
- Confirmed two separate freshness gaps:
  - `data/tracking/pnl_state.json` had `daily_snapshots` and `strategy_daily_snapshots` only through `2026-06-13`.
  - `data/benchmarks/SPY_daily.json` had stopped at `2026-06-12`.
- Root cause was not a tracker schema failure. The real failure was cron execution:
  - recent `paper_demo_*`, `reconciliation`, and benchmark cron runs were often marked `status=ok`
  - but their run summaries explicitly said no `exec` / `process` tool was exposed, so the command never actually ran
- This explains why tracker integrity remained healthy while chart/history data stopped advancing.

### 2. Hardening added
- Updated `scripts/check_cron_health.py` so it now treats these "ok but non-executed" summaries as critical.
- Added regression tests:
  - `tests/unit/test_check_cron_health.py`

### 3. Snapshot backfill tooling added
- Added `scripts/backfill_daily_snapshots.py`.
- Purpose:
  - detect benchmark-backed missing dates after the latest existing snapshot
  - reconstruct `daily_snapshots` equity/unrealized values from broker daily bars + tracker trades
  - rebuild `strategy_daily_snapshots` for the same dates
  - write a timestamped backup before mutating `pnl_state.json`
- Added regression tests:
  - `tests/unit/test_backfill_daily_snapshots.py`
