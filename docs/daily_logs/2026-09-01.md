## 実装内容（shadow-only、observability-only、本番ロジック非変更）

**新規モジュール**: `src/stock_swing/risk/lot_level_exit_diagnostic.py`
- `SimpleExitV2Strategy`が実際に使っている`_resolve_thresholds()` /
  `_resolve_trailing_rule()` / `_resolve_breakeven_floor()` /
  `_effective_min_hold_days()`を**そのまま呼び出して**、各open lot単位で
  独立にexit判定を再評価（ロジックの二重実装を避け、本体とのドリフトを防止）
- symbol単位の集約判定（`generate()`が実際に出したsell signal有無）と
  ロット単位の判定を比較し、food discrepancy（不一致）のみをログ
  - `aggregate_missed_lot_exit`: 集約では見送られたが個別ロットなら発火する
    はずだったケース（NOW実例の型）
  - `aggregate_exit_lot_disagreement`: 逆方向（集約は発火したが個別には
    根拠がないロットを巻き込んでいるケース）
- 一致するケース（discrepancyなし）はログしない（ノイズを避ける）
- **他の全shadow診断（sector_shock_hold/news_shock_hold/volatility_gate/
  distance_from_high）と同じ設計思想を踏襲**: 一切のexit判定・発注ロジックに
  影響しない、observability専用
- config: `LOT_LEVEL_EXIT_DIAGNOSTIC_DISABLED`（デフォルト有効）、
  `LOT_LEVEL_EXIT_DIAGNOSTIC_MIN_LOTS`（デフォルト2、単一ロットは希釈しよう
  がないため評価対象外）

**`SimpleExitV2Strategy`への追加（純粋リファクタリング、動作変更なし）**:
- `build_atr_pct_map()` / `compute_universe_avg_atr_pct()` を
  static methodとして切り出し（`generate()`内部のインライン計算と全く同じ
  ロジック、`generate()`自体の呼び出し経路は変更していない）
- 目的: 診断モジュールが`generate()`が今回runで実際に使った
  volatility-adjusted stopの基準（universe平均ATR%）を**再計算による
  ドリフトなしで**再利用できるようにするため

**配線**: `paper_demo.py`の`exit_strat.generate()`呼び出し直後、
`args.dry_run`でない場合のみ実行。`news_shock_hold`と全く同じ
try/except非致命化パターン（診断が例外を出してもrun全体は継続）。
