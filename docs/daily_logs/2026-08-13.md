## コンソール Open Positions チャート バグ修正

**発覚経緯**: ユーザーからの「コンソールのチャートタブのOpen Position推移は正しいか」という質問を受けて調査。

**バグ内容**:
- `console/services/dashboard_service.py` の `get_charts()` が、各日次スナップショットに
  ポジション数を割り当てる際、その日時点の値ではなく `positions.get("count", 0)`
  （＝呼び出し時点の**現在の**ブローカー/トラッカーからのライブ値）を毎回代入していた
- 結果、Overview タブ・Charts タブ両方の Open Positions チャートが、過去のどの日付でも
  同じ値（今日のポジション数）を表示する**フラットな直線**になっていた
- 根本原因: `DailySnapshot`（`src/stock_swing/tracking/pnl_tracker.py`）に、その時点の
  オープンポジション数を記録するフィールドがそもそも存在しなかった

**修正内容（commit予定）**:
1. `DailySnapshot` に `open_position_count: int | None = None` フィールドを追加
2. `record_daily_snapshot()` が呼び出し時点の open trades 数を記録するように変更
3. `dashboard_service.get_charts()` を各スナップショットの `open_position_count`
   を使うように修正。値が無い（旧データ）場合は `None`（チャート上の欠損点）とし、
   直近1件のみライブ値へのフォールバックを許可（記録がまだない今日のスナップショット用）
4. 既存 167 件の daily_snapshots に対し、trade の entry_time/exit_time から
   日付ごとのオープンポジション数を再構築するバックフィルスクリプト
   `scripts/backfill_open_position_count.py` を新規作成・実行
   - `--dry-run` で事前確認 → `--backup` 付きで本番実行
   - backup: `data/tracking/pnl_state_backup_open_pos_backfill_20260812_234003.json`

**検証結果**:
- バックフィル後、直近の値が 25→25→25→19→19→22→22→22→22→28→28→28→28 と
  実際の履歴どおりに変動することを確認（修正前は全て28固定だった）
- `DashboardService.get_charts()` を実データに対して直接呼び出し、
  end-to-endで正しい値が返ることを確認

**テスト**: 35件新規追加（正常系/境界値/ファイル欠損/backfillスクリプトのdry-run・
本番実行・既存値の非上書き確認・空データ）
- フルテストスイート: 1537 passed / 2 skipped（既存の無関係な2件の失敗のみ、変更前から再現確認済み）

**影響範囲**: メインダッシュボードの Overview タブ（`overviewPositionsChart`）と
Charts タブ（`positionsChart`）

**次のアクション**: なし（修正完了）。既存データの前月分はバックフィル済み、
今後のスナップショットは自動的に正しい値を記録する。

## コンソール Overview タブ「意思決定」デルタ数値 バグ修正

**発覚経緯**: 上記チャート調査に続けて、ユーザーから「概要タブの意思決定の数値もおかしい」
という指摘を受けて調査。

**バグ内容**:
- `dashboard_service.get_deltas()` の `decisions_vs_prev_snapshot` が以下の式で
  計算されていた:
  ```python
  decisions_now = <data/decisions/ の累積ファイル数>
  decisions_prev = max(0, decisions_now - latest_signals)
  decisions_vs_prev_snapshot = decisions_now - decisions_prev
  ```
- この式を展開すると `decisions_now - (decisions_now - latest_signals) = latest_signals`
  となり、**実質「直近runのsignals_generated値」がそのまま表示されているだけ**で、
  実際の意思決定(decision)件数の増減とは無関係な数値だった
- 実データで検証: decisionファイルの日付別実カウントは 08-11=51件 → 08-12=64件
  （実際の増分は **+13件**）だが、画面には常に signals_generated の値（21等）が
  表示される仕組みになっていた

**修正内容**:
1. `DailySnapshot`（`pnl_tracker.py`）に `decisions_generated` フィールドを追加
2. `record_daily_snapshot()` が呼び出し時に、その run で生成された decision 件数を
   記録するように変更（signals_generated / orders_submitted と同じ設計パターン）
3. `paper_demo.py` の `record_daily_snapshot()` 呼び出しに `decisions_generated=len(decisions)`
   を追加
4. `dashboard_service.get_deltas()` を、この新フィールドの前回スナップショットとの
   単純差分を使うように修正（数式のねじれを解消）。旧フィールドが無い過去の
   スナップショットは `None`（表示上「データなし」）とし、無理に推測値を出さない

**バックフィル**: 過去分の正確な `decisions_generated` は、同日に複数回runが
存在し「どのdecisionファイルがどのrunに属するか」を一意に判定できないため、
再構築を断念（無理に推測値を埋めると別の誤情報になるため）。次回run以降は
自動的に正しい値が記録される。

**テスト**: 9件新規追加（record_daily_snapshotへの記録・永続化・get_deltasでの
正しい差分計算・signals_generated値が混入しないことの回帰確認・減少時の負値・
欠損時のNone・単一スナップショット・空データ）
- フルテストスイート: 1546 passed / 2 skipped（既存の無関係な2件の失敗のみ）

**影響範囲**: メインダッシュボードの Overview タブ「📡 意思決定」カードの
deltaバッジ表示のみ（累積カウント自体・パイプライン集計は別ロジックで
影響なし）
