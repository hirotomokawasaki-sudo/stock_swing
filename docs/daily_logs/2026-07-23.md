## 実施内容

### R2-v2 / H5: allocator 統一（commit 5c44a5c）

**方針**: allocator / sizing / console が同一の `portfolio_allocation.yaml` を参照する。
stock 85% / ETF 15% 方針は YAML から単一ソース読み込みへ統一。

#### 新規ファイル

**`src/stock_swing/risk/allocation_config.py`**（新規）
- `AllocationConfig` dataclass: stock_target / etf_target / band / multipliers / caps
- `read_allocation_config(path)`: YAML 読み込み、fail-closed デフォルト（ファイル欠損・破損でも安全）
- `read_symbol_registry(path)`: symbol_registry.yaml → `{SYMBOL: info}` dict
- `get_etf_symbols_from_registry(registry)`: ETF シンボルセット（ハードコードを廃止）
- `classify_symbol(symbol, registry)` → `'etf' | 'stock' | 'unknown'`

#### 更新ファイル

**`portfolio_allocator.py`**（全面リファクタ）
- `__init__`: `AllocationConfig` + symbol_registry を直接受け取れる（テスト用）
- `check_projected_band()`: projected allocation が band_max を超えれば BUY ブロック
- `filter_decisions_by_allocation()`:
  1. symbol_registry に未登録 → BUY ブロック
  2. projected band 超過 → BUY ブロック
  3. 従来の ETF hard cap も維持（二重安全）
- `get_allocation_status()`: band + multipliers も返却（console 表示用）

**`position_sizing.py`**（alloc_config 統合）
- `PositionSizingPolicy(alloc_config=AllocationConfig)`: 省略可
- alloc_config 提供時: YAML の multiplier を `final_shares` に適用、notional cap は base_pct のみ
- 省略時: 従来通り（legacy multiplier を `effective_position_notional_pct` で適用）
- `PositionSizingResult` 新フィールド: `before_multiplier_qty` / `after_multiplier_qty` / `multiplier_applied`

#### 二重適用の回避

旧: `effective_position_notional_pct` で乗数を notional cap に bake-in
新: alloc_config 提供時は `_notional_pct()` が base_pct をそのまま返し、乗数を `final_shares` に 1 回だけ適用
