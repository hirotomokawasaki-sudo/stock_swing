# 2026-08-27（木）

## R15: intraday 5分足データ取得（前夜08-26からの継続、深夜対応）

**背景**: 08-26夜、ユーザーから「今夜Circuit Breaker degradedでBUYが完全ゼロなのは
想定より強すぎないか」との質問を受けreduce_size実効果を再測定（別記事参照）。
その後「バックテストは終値のみで行っているが、これが戦略検討に及ぼす影響は」との
追加指摘を受けた。

**確認した非対称性**:
- 本番（`paper_demo.py`）: premarket/open/midday/closeの**1日4回**cron実行、
  exitは`broker.fetch_positions()`のリアルタイムcurrent_priceで評価、breakout
  候補には**5分足intraday bar**を取得した二段階判定（`PAPER_DEMO_USE_INTRADAY=
  true`がデフォルト）
- バックテスト（R11-B〜R13-C、R14、R13-D、08-26に検証で使い倒した全エンジン）:
  全て**日足OHLC**（`data/r11_price_cache/*.json`）のみ、1日1回判定
- intraday機能は本番の実際の意思決定パスの一部だが、**一度もバックテストで
  検証されたことがない**

**この非対称性と08-26発見の関連**: R11-C RSI逆張り検証で見つけた「1銘柄1
ポジション排他制御によるタイミングシフト効果」は、日足という粒度の粗さ
（1日1回しかエントリー機会を判定できない）が引き起こした側面がある可能性を指摘。

**データ取得実施**: `broker.fetch_bars(timeframe="5Min")`（本番の`fetch_
intraday_bars()`と同一メソッド・同一feed="iex"）で、既存日足キャッシュと
完全に同じ期間（2024-08-15〜2026-08-14、2年分）・同じ69銘柄について5分足を
新規取得。

**実施内容**:
- 新規`scripts/r15_fetch_intraday_5min_history.py`作成
- 1銘柄でドライテスト（NVDA、42,271バー、30秒）→問題なし確認後、全69銘柄で
  本実行
- 実行時間: 21.9分（1,725 API呼び出し想定、実際は成功分のみ）
- 初回実行で6銘柄（CHPS/CHPX/FRWD/GTOP/NBIS/TTEQ）が失敗。原因は自己発見バグ:
  `payload.get("bars", [])`が、キー自体は存在し値が`None`のケース（低流動性
  銘柄で該当月に取引なし）を拾えず`None`を返し、これをiterateしようとして
  例外。`(payload.get("bars") if isinstance(payload, dict) else payload) or []`
  に修正し、失敗6銘柄を再取得して全件成功
- 最終結果: **全69銘柄成功**（`data/r15_intraday_5min_cache/`、合計211MB）。
  マニフェスト（`_manifest.json`）で取得範囲・feed種別を記録
- 日本株11銘柄（`.T`サフィックス）はAlpaca APIが非対応（400エラー）のため
  意図的にスキップ（既存日足キャッシュと同じ69銘柄=米国株のみのユニバースに
  合わせた設計、レジストリ全体ではなく既存キャッシュから銘柄リストを導出する
  よう実装）

**次のアクション（未実施）**: このintraday 5分足キャッシュを使った、本番の
実際の判断粒度（日中複数回判定・intraday二段階エントリー判定）を再現する
新規バックテストエンジンの構築。R11-C等で見つかったアーティファクトが
intraday粒度でも再現するかの確認、および現行の日足ベースPF数値がどの程度
過大/過小評価されているかの定量化が目的。

詳細: データのみ、レポート未作成（次回のバックテストエンジン構築時に
分析結果とあわせて作成予定）

## R15続き: intraday対応バックテストエンジン構築・初回検証

**実装したメカニズム（`paper_demo.py`/`IntradayMomentumFeature`を実読して確認）**:
日足breakoutシグナルの候補のみ、直近5分足100本で`smoothed_momentum>0.3%`かつ
`vwap_signal!=below_vwap`なら`signal_strength`を1.2倍（上限1.0）にブーストするだけで、
どの条件でもシグナルをブロックしないこと、exit判定には一切関与しないことを確認。

**新規`scripts/r15_intraday_backtest_engine.py`**: v4エンジンをベースに、R15で取得した
実5分足データを使ってこのブースト判定を忠実に再現するレイヤーを追加。
`use_intraday_boost=False`でv4本家のbaseline（n=633, PF=1.9251, net=
$107,375.5）と**完全一致**することを確認（サニティチェック合格）。

**結果**: intraday boost有効化後、PF 1.9251→1.9410（+0.83%）、net_pnl $107,375.5→
$108,648.41（+1.19%）。候補626件中267件（42.7%）が実際にブーストされた。件数（n=633）
は両方で同一（entry/exitのタイミング自体は変えず、signal_strengthのみ変更する実装の
正しさを裏付ける）。

**結論**: intraday boostの効果は小さく、方向性は正（微改善）。これまでのR11-B〜R14の
日足のみ検証によるPF数値は、intraday機能を欠いていたとしても大枠の結論（エッジの
有無、候補間の優劣）を覚すほどの誤差ではなかったと判断できる。一方でexit側の
日中複数回判定の精度は今回の検証範囲外であり、引き続き未解決。

詳細: `docs/r15_intraday_backtest_20260827/README.md`

**教訓**: 08-26の一連の検証で発見した「バックテスト実装の粒度が戦略効果と見分けが
つかない」という懸念を、実際の本番メカニズムを忠実に再現して定量検証したことで、
「懸念は存在するが影響は限定的」という定量的な結論に到達できた。想像で不安を
抱えるだけでなく、実際に測定することで安心材料を得られた。
