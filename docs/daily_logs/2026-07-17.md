# 2026-07-17 実装ログ — sector_shock shadow データ取得修正

## 背景

07-11〜07-16 の shadow 累計6件を分析したところ、5件が `no_sector_data → hard_stop` にフォールバックしており、sector shock の regime 判定が実質機能していなかった。
A/B テストに向けて修正を実施。

---

## 修正内容（commit f6f1f6f）

### Fix 1: sector 1d return に benchmark_returns.csv フォールバック追加

**原因**:
`paper_demo.py` は `all_features` から SMH/SOXX の `return_1d` を取得しようとしていたが、
`price_momentum_feature` の計算に必要な「直近2本のバー」が揃っていない場合 `return_1d = None` になり、
`_sector_1d = {}` (空) → `no_sector_data` に落ちていた。

**修正**:
1. 全シンボルの `return_1d` を先にマップ化（`_feat_return_1d`）
2. SMH/SOXX が features に含まれない場合のみ、`data/benchmarks/benchmark_returns.csv` の最新行を読み込んでフォールバック
3. `benchmark_returns.csv` は毎日 `stock_swing_update_benchmark_all` cron で更新済み（最新: 07-16）

### Fix 2: symbol 1d return を features から直接取得

**原因**:
`_1d_sym = signal_strength * -1` という proxy を使っていた。`signal_strength` はエントリー時の強さであり、当日の価格変動ではない。

**修正**:
`_feat_return_1d.get(symbol, fallback_proxy)` で price_momentum feature の実値を使用。

## 修正の効果

| ケース | 修正前 | 修正後 |
|---|---|---|
| 07-11 JST (SMH +0.5%, SOXX -0.1%) | `no_sector_data → hard_stop` | `soft_stop (monitor)` ✅ |
| 07-16 US (SMH -3.7%, SOXX -4.5%) | `no_sector_data → hard_stop` | `sector_shock_hold (hold)` ✅ |
| データなし（真のno_sector_data）| `hard_stop` | `hard_stop` ✅（変更なし） |

**重要な発見**:
- 07-16 の NOW/DELL stop_loss は「sector shock 当日（SMH -3.7%）」に発動していた
- 修正済みコードなら `sector_shock_hold (hold)` 推奨が出ていた
- A/B テストを実施していれば保有継続 vs 売りの比較ができていた
