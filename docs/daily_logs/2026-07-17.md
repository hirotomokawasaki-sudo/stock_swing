# 2026-07-17 実装ログ — sector_shock shadow データ取得修正

## 背景

07-11〜07-16 の shadow 累計6件を分析したところ、5件が `no_sector_data → hard_stop` にフォールバックしており、sector shock の regime 判定が実質機能していなかった。
A/B テストに向けて修正を実施。

---

## 修正内容（commit f6f1f6f）

### Fix 1: sector 1d return に benchmark_returns.csv フォールバック追加

**原因**:
`paper_demo.py` は `all_features` から SMH/SOXX の `return_1d` を取得しようとしていたが、
`price_momentum_feature` の計算に必要な「直近2本のバー」が揃っていない場合 `return_1d = None` になり、
`_sector_1d = {}` (空) → `no_sector_data` に落ちていた。

**修正**:
1. 全シンボルの `return_1d` を先にマップ化（`_feat_return_1d`）
2. SMH/SOXX が features に含まれない場合のみ、`data/benchmarks/benchmark_returns.csv` の最新行を読み込んでフォールバック
3. `benchmark_returns.csv` は毎日 `stock_swing_update_benchmark_all` cron で更新済み（最新: 07-16）

### Fix 2: symbol 1d return を features から直接取得

**原因**:
`_1d_sym = signal_strength * -1` という proxy を使っていた。`signal_strength` はエントリー時の強さであり、当日の価格変動ではない。

**修正**:
`_feat_return_1d.get(symbol, fallback_proxy)` で price_momentum feature の実値を使用。

# タスク2: attribution 破損の発見・修復・再発防止

## 発見した問題

07-14 10:38 の `rebuild_pnl_state_from_broker.py` 再実行（CRWD split fix）で attribution が全損:
- quarantined_trades: 54 → 0
- broker_fill: 54 → 244/255件（全クローズが broker_fill にリセット）

## 原因

スクリプトの設計上の欠陥: 全 exit_reason を `broker_fill` で上書きし、`quarantined_trades` を保存しない。
07-13/14 に G1 HALT 解除と CRWD split fix で合計2回 rebuild が実行された。

## 応急修復（2026-07-17 commit a6065de）

- 07-14 09:07 バックアップから (symbol, exit_time, pnl) キーで attribution を復元
- 169/244 件を修復（75件は trade_id 変更でマッチ不能）
- quarantined_trades = 54 件復元
- 修復後 clean PF: 0.663（n=178）

## 根本対策（2026-07-17 commit b1ce8b7）

`rebuild_pnl_state_from_broker.py` に `--preserve-attribution` フラグを追加:

```bash
# 今後の rebuild はこのコマンドを使う
python scripts/rebuild_pnl_state_from_broker.py --backup --preserve-attribution
```

- rebuild 前に exit_reason + quarantined_trades を読み込み
- rebuild 後に attribution を再適用
- フラグなし時は「attribution が失われる」警告を表示
- テスト 13件追加（752 passed）
