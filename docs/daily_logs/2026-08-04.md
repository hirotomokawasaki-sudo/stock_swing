# 2026-08-04 デイリーログ

## 1. 🚨 Circuit Breaker HALT 発生・恒久修正・クリア（SNOW BUY qty lag）

### 発見の経緯

OpenClaw ダッシュボードから「現在対応が必要な問題はありますか」との問いに応じて定常監査を実施したところ、
`data/guardrails/circuit_breaker.json` が `08-03 19:55 JST` から `halted` のまま放置されていることを発見。
manual clear がない限り `apply_decision()` は絶対に halted から自動復帰しない実装のため、
このまま気づかなければ 08-04 22:25 JST の premarket 以降、全 cron で新規 BUY が停止するところだった。

### 根本原因

- SNOW は既に 116株のオープンポジションを保有していた
- 08-03 19:55 JST run で同銘柄にさらに 116株の BUY を追加発注
- トラッカーは発注と同時に qty を 232 に即時合算するが、broker 側の position qty は
  Alpaca の fill確認 + API伝播が完了するまで数秒ラグがある
- postrun の broker/tracker 整合性チェックがこのラグの最中（fill完了の約4秒前）に走り、
  `broker_qty=116` vs `tracker_qty=232` の qty_mismatch を検知 → `broker_tracker_mismatch`
  ルール（閾値1件でcritical）が発火 → 即HALT
- これは G1-v2（BUY presence lag）/ G1-v2-b（SELL qty lag）/ G1-v2-c（fast-fill SELL phantom）
  と同系統だが、「既存ポジションへの追加BUYによるqtyラグ」という**未対応の第4パターン（G1-v2-d）**だった

### 検証

- ブローカーへ直接問い合わせ、現在は broker側もqty=232でトラッカーと完全一致（全7銘柄でmismatch=0）を確認
- 誤検知であることを確認した上で `scripts/clear_circuit_breaker.py --confirmed-mismatch-count 0` で手動クリア

### 恒久修正（commit `f61586b`、push済み）

- `src/stock_swing/guardrails/postrun_mismatch.py`: `apply_lag_exclusion()` に G1-v2-d ルール追加
  - qty_mismatches のうち、symbol が今回run の new_buy_symbols に含まれ、かつ
    `tracker_qty > broker_qty`（トラッカーが先行している方向）の場合のみ除外
  - 逆方向（`broker_qty > tracker_qty` の BUY symbol）は別の実問題として除外しない
- テスト: `TestG1V2dBuyAddToExistingPositionQtyLag`（8件、SNOW再現テスト含む）追加
- 既存テスト1件（`test_buy_symbol_qty_mismatch_not_excused`）を broker-ahead 方向のテストに更新
  （新ルールで正当に除外される方向の値を使っていたため）
- フルテスト: 1276 passed, 2 skipped（既存の無関係な2件の失敗は本修正前から存在すること確認済み）

### 今後の確認事項
