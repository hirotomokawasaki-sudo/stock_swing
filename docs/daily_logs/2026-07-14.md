## 追加修正（10:31 JST 対応）

### 問題1: CRWD split 調整不足（rebuild スクリプト）

**根本原因**
- rebuild スクリプトの FIFO マッチングが、split 前後の fill を素通りでマッチング
- CRWD buy: 2026-06-29 @ $721.75（pre-split）/ sell: 2026-07-06 @ $194.79（post-split）
- 4:1 split を考慮せずに PnL = (194.79 - 721.75) × 43 = **-$22,659** と計算（誤り）
- 正しくは: entry = $721.75 / 4 = $180.44 → PnL = (194.79 - 180.44) × 43 = **+$617**

**修正内容（commit: a6938d7）**
- `load_corporate_actions()` 追加: `data/corporate_actions.json` を読み込む
- `apply_split_adjustment()` 追加: buy/sell が split ex_date をまたぐ場合に entry 価格を ratio で除算
- `match_buy_sell_orders()` に `corporate_actions` 引数を追加して接続
- pnl_state.json の CRWD トレード PnL を手動パッチ: -$22,659.39 → **+$617.16**
- 累積 PnL: -$115,152 → **-$91,876**（$23,276 改善）
- 次回 rebuild からは自動で正しく計算される

**単体テスト 4ケース ✅**

### 問題2: FRWD 0-qty SELL が order_rejection_rate_pct を押し上げる

**根本原因**
- `_prefilter_actionable_buys_for_submission()` は BUY のみを preflight でフィルタリング
- SELL は unconditionally `filtered.append(decision)` → 0-qty SELL がそのまま通過
- FRWD: tracker は open 扱い → exit シグナル生成 → broker にポジションなし → qty=0 の SELL 試行
- これが rejection rate の 12.5% 発生原因（→ `order_rejection_rate_pct >= 10%` ルールで HALT）

**修正内容（commit: a6938d7）**
- paper_demo.py のサブミットループ先頭に SELL guard を追加
- `current_positions.get(o.symbol, 0) <= 0` の場合は submit をスキップ
- `SKIP SELL {symbol}: no broker position (broker_qty=0)` を出力
- `sell_skipped_no_broker_position` を WARNING ログに記録（追跡可能）

**効果**
- broker でクローズ済みポジションへの 0-qty SELL が完全にブロックされる
- rejection_rate の誤加算を防ぎ、circuit breaker の誤 HALT リスクを解消
- tracker rebuild まで SELL の誤発動が起きても circuit breaker は影響を受けない
